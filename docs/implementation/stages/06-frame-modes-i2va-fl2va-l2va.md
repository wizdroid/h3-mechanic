## 1. Stage Overview & Scope

Implement the three image-to-video frame continuity modes: **I2VA** (first-frame anchor), **FL2VA** (first-and-last frame transition), and **L2VA** (last-frame convergence). This stage enforces locked `adaptive` ratios, app-generated byte-exact instruction lines, and the single-shot FL2VA rule waiver.

### Deliverables:
1. `app/web/js/modes/frame_modes.js`: Reusable UI module powering the three frame mode tabs:
   - I2VA: `<Picture 1>` (first frame).
   - FL2VA: `<Picture 1>` (first frame) and `<Picture 2>` (last frame), with `requested_shot_count` defaulting to 1.
   - L2VA: `<Picture 1>` (last frame).
   - Read-only instruction line preview panel.
2. `app/api/frame_routes.py`: Backend route handlers running `frame_action_elaboration` → `prose_writer` → deterministic render → preflight.
3. Instruction line engine integration:
   - Rendering byte-exact lines with em dashes (`—`, U+2014) and dynamically computed shot count $N$ and duration $S.SS$.
4. `tests/test_stage_06.py`: Test suite verifying byte-exact instruction line outputs, locked `adaptive` ratio, forbidden reference tokens (`<Subject>`, `<Audio>`, `<Video>`), and 1-shot FL2VA export.

## 2. Step-by-Step Implementation Instructions

### Step 6.1: Frame Mode Form Component (`app/web/js/modes/frame_modes.js`)
- **Shared Input Fields:**
  - Frame token cards with caption and optional `width_px`/`height_px` inputs.
  - Action / Transition text input.
  - Read-only instruction line preview (labelled "preview; computed after planning").
  - Dialogue lines and audio policy controls.
- **Mode-Specific Gating:**
  - **I2VA:** Exactly 1 image reference (`role_hint = 'first_frame'`). Ratio locked to `adaptive`.
  - **FL2VA:** Exactly 2 image references (`first_frame` at position 1, `last_frame` at position 2). Shots control defaults to 1.
  - **L2VA:** Exactly 1 image reference (`role_hint = 'last_frame'`). Ratio locked to `adaptive`.

### Step 6.2: Frame Elaboration Pipeline (`app/api/frame_routes.py`)
Implement the frame pipeline:
1. **Stage 0 Checks:**
   - Ratio must be `adaptive` (PF-11).
   - I2VA/L2VA must have exactly 1 image; FL2VA must have exactly 2 images.
   - Forbid `<Subject>`, `<Audio>`, `<Video>` tokens (PF-27).
2. **`frame_action_elaboration`:**
   - Meta-prompt from §8.2 parameterised by mode, frames, action, and duration.
   - Produce JSON shots with start/end times, composition, action chain, camera verb, and expressions.
   - Single-shot FL2VA exception: If `requested_shot_count == 1`, waive PF-03 shot count minimum (Criterion A-12).
3. **`prose_writer`:**
   - Synthesize shot prose following mode path rules:
     - I2VA: anchor → onset → continuous development → result.
     - FL2VA: describe motion *between* frames; final shot lands on `<Picture 2>`.
     - L2VA: plausible preceding state → action → convergence onto `<Picture 1>`.
4. **Renderer Assembly:**
   - Prepend exact mode instruction line followed by `\n\n`.
   - Append `integrated_multimodal_description: `, `overall_soundscape: `, and `non_diegetic_music: `.

### Step 6.3: Instruction Line Formatting Contract
Ensure byte-level compliance with Appendix A.2:
- **I2VA:**
  ```text
  For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.
  ```
- **FL2VA:**
  ```text
  How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.
  ```
  *(Note: No angle brackets around Picture 1/2; no square brackets around Shot 1/N; em dash U+2014; `S.SS` is `str(duration_s) + ".00"`).*
- **L2VA:**
  ```text
  How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.
  ```
  *(Note: Angle brackets around `<Picture 1>` and square brackets around `[Shot N]` are preserved; em dash U+2014).*
